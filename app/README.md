# WORD LAB 단어시험지 생성기

Windows PowerShell과 Edge 또는 Chrome으로 실행하는 정적 웹앱입니다. 앱 실행에 Python·Node.js 설치는 필요하지 않습니다. 별도 제작된 데스크톱 실행파일의 소스와 배포물은 이 저장소에 포함되어 있지 않습니다.

## 실행

1. 저장소 전체를 원하는 작업 폴더에 둡니다. `START.bat`, `wordlab-server.ps1`, `app/firebase-config.js`, `app/vendor/`가 함께 있어야 합니다.
2. 루트의 `START.bat`을 실행합니다.
3. 브라우저에서 `http://127.0.0.1:8763/app/index.html`이 열립니다. HTML 파일을 직접 열지 마세요.

이미 실행 중인 서버는 이 작업 폴더의 서버인지 확인한 뒤 재사용합니다. 다른 폴더 또는 이전 버전의 서버가 8763 포트를 사용한다는 안내가 나오면 기존 WORD LAB 서버를 종료하고 다시 실행하세요. 다른 프로그램이나 PowerShell 작업을 임의로 종료하지 마세요.

입력 데이터는 같은 브라우저 프로필과 같은 주소에서 복원됩니다. `localhost`, 다른 포트, 다른 브라우저는 별도 저장 공간을 사용하므로 옮기기 전 `입력 백업`을 저장하세요. 코드 폴더와 PDF 저장 폴더는 서로 다릅니다.

## 사용 방법

1. 반 그룹을 고르고 각 반에 이름과 `단어[TAB]뜻`을 입력합니다.
2. 담당 선생님, 자료 날짜, 출제 방향, 문항 수(5~100), 차수(1~5)를 고릅니다.
3. 반별 오류·주의 안내와 생성 폴더명 미리보기를 확인합니다.
4. `저장 폴더 연결`로 PDF를 보관할 일반 하위 폴더를 선택합니다. 예: `바탕화면/WORD LAB OUTPUT`.
5. `PDF 생성 시작`을 누릅니다. 시험지·답지에는 선택한 자료 날짜가 인쇄됩니다.

출력 예시:

```text
선택한 저장 루트/
  홍길동_2030-01-02/
    2강서A/2강서A_1차.pdf
    2강서A/2강서A_1차_답지.pdf
    WORD_LAB_단어복원.json
  홍길동_2030-01-02.zip
```

선생님이 비어 있으면 날짜만 사용합니다. 같은 폴더·파일·ZIP 이름이 있으면 폴더와 ZIP에 함께 `_2`, `_3`을 붙입니다. 긴 뜻은 글꼴 크기와 비율을 유지하며 다음 A4 페이지로 넘깁니다. 한 문항 자체가 인쇄 영역보다 크면 입력을 수정하도록 안내합니다.

짧은 단어·뜻의 100문항은 50문항씩 2쪽에 배치합니다. 여러 쪽에서는 차수와 쪽수 배지를 같은 줄에 표시해 용지를 절약하며, 긴 내용은 필요한 만큼 페이지를 늘립니다.

## 저장 폴더 다시 연결

- 같은 브라우저에서 `저장 폴더 다시 연결`을 누르고 권한을 허용합니다.
- 폴더를 옮겼거나 다른 폴더를 쓰려면 `저장 폴더 연결/변경`으로 해당 폴더를 다시 선택합니다.
- 시작 시 이전 폴더 복원이 늦어져도 그 사이 새로 연결한 폴더를 우선합니다.
- Desktop·Documents·Downloads의 루트 자체는 브라우저가 막을 수 있으므로 그 아래의 일반 폴더를 선택하세요.
- 브라우저·프로필을 바꿀 때는 백업 JSON을 복원하세요.

## 입력 보호와 저장 결과

- `입력 백업`은 두 반 그룹과 설정을 WORD LAB 버전 1 JSON으로 내려받습니다. `파일 복원`은 형식을 검사하고 교체 여부를 확인합니다.
- 복원·예시 채우기·반 삭제 후 `직전 입력 되돌리기`로 한 단계 복구할 수 있습니다. 이 복구 내용은 현재 탭에만 있으므로 닫거나 새로고침하기 전에 백업하세요.
- 자동 저장 실패 경고가 나오면 `자동 저장 다시 시도` 또는 `입력 백업`을 사용하세요.
- 충돌·미저장 상태에서는 로그인 응답이 와도 현재 초안을 교체하지 않습니다. 충돌 안내가 표시되면 입력 백업을 저장한 뒤 안내에 따라 다시 여세요.
- 같은 브라우저·같은 주소에서는 입력 편집 탭 하나만 사용합니다. 추가 탭은 읽기 전용이며 입력 백업·출력은 가능합니다. 편집 탭을 닫은 후 `이 탭의 편집권 확인`을 누르면 최신 저장 입력을 불러옵니다. 다른 버전의 오래 열린 탭이나 외부 저장 변경을 감지하면 현재 입력을 유지하고 편집을 멈추므로 백업한 뒤 새로고침하세요.
- 생성 중 입력을 잠그며 저장된 PDF 수와 현재 반·차수, PDF·복원 JSON·ZIP 결과를 표시합니다. JSON 개별 저장이 실패해도 정상 생성된 ZIP에는 복원 JSON이 포함됩니다. 일부 실패 시 이미 저장한 파일은 삭제하지 않습니다.
- 같은 브라우저·같은 주소의 여러 탭은 출력을 순서대로 처리합니다. 다른 브라우저나 별도 데스크톱 호스트의 동시 출력까지 보호하지는 않으므로 같은 저장 폴더에 동시에 생성하지 마세요.
- 선택적 로그인 기본 설정은 로컬 입력 복원 후 확인합니다. 그 사이 편집한 로컬 입력은 새로고침 뒤에도 유지합니다. `로그인 저장 입력 열기` / `로컬 저장 입력 열기`로 저장 범위를 선택하며, 양쪽 원본을 덮어쓰거나 이동시키지 않습니다. 자동 저장 실패 중에는 범위를 바꾸지 않습니다. 다른 계정으로 로그인했다면 입력을 백업하고 새로고침한 뒤 원하는 저장 범위를 선택하세요.
- 문항 수는 5~100의 정수여야 합니다. 범위를 벗어나거나 비어 있으면 입력란에 오류를 표시하고 폴더 선택·출력을 시작하지 않습니다.

## 입력 형식과 중복 규칙

- 권장: `단어[TAB]뜻`. Excel의 인용된 여러 줄 셀과 `""` 이스케이프를 지원합니다.
- 추가 지원: `단어 | 뜻`, `단어, 뜻`, `단어  뜻`(두 칸 이상 공백).
- 닫히지 않은 인용부호 등 잘못된 줄은 제외 위치를 안내합니다. 단어 수와 제외 줄 수를 확인하고 수정하세요.
- 같은 단어는 대소문자를 구분하지 않고 뜻을 합칩니다. 단어가 `문항 수 × 차수`보다 적으면 차수 사이에 일부 중복이 생길 수 있습니다.

## 개발 회귀 검사

저장소 루트에서 실행합니다.

```text
node --test tests/regressions.test.cjs tests/p2.test.cjs tests/p3.test.cjs tests/final-fixes.test.cjs tests/server.test.cjs tests/print-layout.test.cjs
```

합성 데이터·가상 핸들과 격리 포트의 임시 서버를 사용합니다. 사용자 저장 폴더나 Firebase에 쓰지 않습니다. Node.js는 개발 검사에만 사용합니다.

PDF 브라우저 재현 화면은 `node tests/build-browser-fixture.cjs <새 절대 경로>`로 만듭니다. 이 임시 폴더를 서버의 `-Root`로 지정하고 별도 포트에서 `/app/index.html`을 열어 검사합니다. 실제 출력 함수·CSS·vendor로 일반/긴 뜻과 50/100문항을 생성하고 시험지·답지의 문항 번호·페이지·행 위치·높이를 대조합니다.

시험지와 답지는 같은 페이지·열·행 높이를 사용합니다. 50문항 이하는 A4 한 쪽에 출력하며, 필요하면 글자 크기를 유지하고 헤더·행 간격만 줄입니다. 50문항 페이지는 각 열의 박스 높이에 남는 공간을 나눠 하단까지 채웁니다. 매우 긴 설명으로 한 쪽을 넘으면 내용을 자르거나 글자를 축소하지 않고 오류를 표시합니다. 해당 뜻을 줄이거나 문항 수를 줄여 다시 생성하세요. 50문항을 초과할 때도 시험지·답지의 페이지 구분은 같습니다.

vendor 버전·공식 출처·파일 해시는 `vendor/manifest.json`에 기록합니다. 배포는 자동 수행하지 않습니다.

ZIP은 무압축 classic ZIP으로 생성하며 중간 PDF 복사본 없이 최종 버퍼에 기록합니다. 4 GiB 또는 65,535개 항목을 초과하는 출력은 반·차수를 나눠 생성하세요. UI는 운영체제의 모션 줄이기 설정을 따릅니다.

입력 편집 보호에도 Web Locks를 사용하므로 이를 지원하지 않는 브라우저에서는 읽기 전용으로 시작합니다. 기존 입력 키와 버전 1 백업 형식은 유지하고, 마지막 저장 범위 선택만 별도 설정 키에 보관합니다. 되돌리기는 해당 저장 범위에서만 동작합니다.
